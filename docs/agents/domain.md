# Documentación del dominio

## Lectura antes de explorar el código

- Lee `GLOSSARY.md` en la raíz cuando exista.
- Consulta en `docs/adr/` las decisiones relacionadas con el trabajo.

Si todavía no existen, continúa sin crear archivos vacíos ni proponer
su creación por adelantado. La skill `domain-modeling` los irá creando
cuando se acuerden términos o decisiones.

## Estructura

Este repositorio usa un único contexto:

- `GLOSSARY.md`: vocabulario compartido del dominio.
- `docs/adr/`: decisiones de arquitectura.

## Uso del vocabulario y las decisiones

Usa los términos acordados en el glosario al nombrar conceptos del dominio.
Si falta un término necesario, registra esa carencia para `domain-modeling`.

Si una propuesta contradice un ADR vigente, señala el conflicto y explica
el motivo antes de proponer su modificación.
